# 画面仕様書

## 目的

本ドキュメントは `要件定義書.md` の機能要件を実現するための画面構成・画面遷移・各画面の表示項目/操作を定義する。

- 定義の一次情報源は `要件定義書.md` です。本ドキュメントと齟齬がある場合は要件定義書を優先してください。
- 用語の表記は `用語集.md` に準拠します。
- 本書は画面一覧・表形式の仕様・簡易テキストワイヤーフレームの粒度で記述し、詳細なビジュアルデザイン（配色・フォント等）は対象外とする。

## 共通仕様

### 共通ヘッダー（管理者画面）

全管理者画面（A2〜A8）はヘッダーとナビゲーションを共有する。大会単位の画面（A3・A4・A5・A6・A7）を開いている間は、ヘッダー右側に「データ出力」ボタンを追加表示し、対象大会の[A7 データ出力画面]へ遷移する。大会に属さない画面（A2・A8）では「データ出力」は表示しない。

> **現状の注記（2026-11時点）**: 「データ出力」ボタン（`AdminHeader.tsx`）および下記の大会名ヘッダーに表示される参加者向け閲覧URL（`TournamentHeaderBlock.tsx`）は、一旦保留としてコメントアウトしており、通常のUI操作では表示・到達できない（CLAUDE.md「現在の状態」参照）。[A7 データ出力画面]・[P1 大会結果閲覧画面]自体や対応するAPIは削除しておらず、URLを直接開けば動作する。本節および以降のワイヤーフレームは、再有効化した場合の設計を示す。

```
+----------------------------------------------------------------+
| リーグ戦しようよ                    [データ出力] [バックアップ] [ログアウト] |
+----------------------------------------------------------------+
```

大会単位の画面のうち、A3・A4・A5・A6は、大会名ヘッダー（大会名を改行表示し、大会情報画面に準じた強調フォントで装飾する）・ステータスバッジ・参加者向け閲覧URL（コピーボタン付き）を共通で表示する。A3・A4・A5はこれに続けて共通タブ（[大会情報][競技情報][選手(チーム)]の3つ）で画面を切り替える。A6もこの大会名ヘッダーの下に共通タブを表示するが、どのタブもアクティブにしない（詳細はA6の節を参照）。試合・順位表（A6）とデータ出力（A7）はこの共通タブに含めない（A6への入口・A7への入口は後述のとおり別に設ける）。A7・A8は共通タブを持たず、大会名または大会一覧へ戻るリンクのみを表示する（詳細は各画面の節を参照）。

大会ステータス別のボタン群（「リーグ表を作成する」「大会を開催する」「大会を終了する」「大会を閲覧する」「大会を再開する」。詳細はA3の節を参照）は、A3だけでなくA4・A5でも共通タブの直上の同じ位置に表示し、どのタブを開いていても画面を移動せずに操作できるようにする。

```
+----------------------------------------------------------------+
| ← 大会一覧                                                        |
| バレーボール大会                                                   |
| 2026/11/09・体育館                                                |
| [進行中]                                                          |
| 参加者向けURL: https://.../t/volleyball  [コピー]                 |
+----------------------------------------------------------------+
| [ リーグ表を作成する ] [ 大会を開催する ] [ 大会を終了する ]         |   ← A3・A4・A5共通表示
+----------------------------------------------------------------+
| [大会情報] [競技情報] [選手(チーム)]                                |
+----------------------------------------------------------------+
```

競技情報（A4）・試合・順位表（A6）はカテゴリ単位の機能のため、共通タブ（またはA6の場合は戻りリンク）の下にカテゴリタブを表示する。カテゴリタブのラベルは、カテゴリ選択コンボボックスと同様に「カテゴリX：カテゴリ名」の形式で表示する（カテゴリ名を省略しない）。試合・順位表（A6）はさらにコートタブを表示する（競技情報登録のコート数が2以上かつ独立リーグの場合のみ。単一リーグの場合は表示しない）。選手(チーム)情報（A5）は要件定義書上カテゴリ別の機能ではないため、カテゴリタブは設けない（一覧の各行にカテゴリ列を表示し、登録フォーム内でカテゴリを選択する）。

```
+----------------------------------------------------------------+
| [カテゴリA：フリー] [カテゴリB：初級] [カテゴリC：上級]                |   ← A4・A6のみ
+----------------------------------------------------------------+
| [コート1] [コート2]                                               |   ← A6のみ（コート数2以上の場合）
+----------------------------------------------------------------+
```

試合・順位表（A6）への入口は、大会情報画面（A3）の「大会開催」ボタン（1つでも生成済みカテゴリがあれば活性）と「大会を閲覧する」ボタン（大会ステータス＝終了、または閲覧モードの場合）の2つのみとする。リーグ表・試合順・審判順の生成・再生成はA3の「リーグ表を作成する」ボタンからのみ行い、A6自身には生成・再生成ボタンを設けない。A6を開いた後は、共通タブ（[大会情報][競技情報][選手(チーム)]）から他画面へ移動できる。

### 認証・セッション

- A1でのログイン成功時にサーバー側でセッションを発行し、Cookieで保持する。以降、管理者向け画面（A2〜A8）およびそのAPIは、このセッションが有効な場合のみアクセスできる。
- セッションが無効な状態で管理者向け画面にアクセスした場合は、A1（ログイン画面）へ自動的にリダイレクトする。
- ログインID・パスワードは初期状態で1組シードされており、A1ログイン画面のダイアログからいつでも変更できる（詳細はA1の節「ログイン情報の変更」を参照）。

### ログアウト確認

共通ヘッダーの「ログアウト」ボタンをクリックすると、以下の2段階の確認を経てログアウトを実行する。

1. 「ログアウトしますか？」（しない／ログアウトする）を表示する。「しない」を選ぶとダイアログを閉じ、何も実行しない。
2. 1で「ログアウトする」を選んだ場合のみ、続けて「バックアップを作成しますか？」（しない／バックアップする）を表示する。いずれを選んでもその選択に従ってバックアップ作成の有無を決定したうえでログアウトを実行し、[A1 ログイン画面]へ遷移する。

### ウィンドウ・タブを閉じる場合の挙動

ブラウザの技術的制約上、JavaScriptからは「タブ・ウィンドウを閉じた」場合と「ページを再読み込み／別画面へ遷移した」場合を区別できず、またページ離脱時に独自の文言で確認ダイアログを表示することもできない（ブラウザ標準の汎用的な確認文言のみ表示可能であり、本アプリはこれを使用しない）。そのため、ウィンドウ・タブを閉じる操作（×ボタン等）は、上記「ログアウト確認」とは異なり確認なしのベストエフォートで自動バックアップのみを試みる（ログアウト自体は行われず、セッションは有効なまま維持される）。これはブラウザの仕様に起因する意図的な設計上の制限であり、不具合ではない。

### 共通バリデーション表示

- `要件定義書.md` 3章冒頭の規定に従い、MAX文字数超過・範囲外の数値はエラーメッセージを表示して保存を拒否する（自動切り詰めは行わない）。
- エラーは該当入力欄の直下に赤字で表示する。
- 文字数上限（MAX文字数）が定義されているテキスト入力欄は、ラベルに「（最大n文字）」の形式で上限文字数を併記する。

### 共通確認ダイアログ

以下の操作は実行前に確認ダイアログを表示する（要件定義書の該当条件を参照）。

| 操作 | ダイアログ文言例 |
|---|---|
| 大会の削除（A2のみ） | 「この大会を削除すると、紐づく競技情報・選手(チーム)情報・試合・試合結果がすべて削除されます。元に戻せません。削除しますか？」 |
| 大会の終了（A3「大会を終了する」ボタン） | 「大会を終了すると、大会情報・競技情報・選手(チーム)情報の編集、試合結果の入力・修正ができなくなります。終了しますか？」 |
| バックアップからの復元（リストア） | 「現在のすべてのデータが、選択したバックアップ（作成日時）の内容で完全に上書きされます。元に戻せません。復元しますか？」（1. バックアップデータの選択→2. 復元ボタン押下に続けて表示する最終確認） |
| リーグ表作成時のエラー（想定を超える選手(チーム)数） | 「想定を超える選手(チーム)が登録されています。競技情報のコート数、または、１コート最大選手(チーム)数を変更して下さい。」 |
| リーグ表作成時のエラー（試合結果が入力済み） | 「試合結果が入力されています。試合結果を削除して下さい。」 |
| 「大会を閲覧する」クリック時のエラー（リーグ表未生成） | 「まだリーグ表が生成されていません。大会情報画面の「リーグ表を作成する」から生成してください。」 |

※ 試合（リーグ表・試合順・審判順）の再生成は、独立した確認ダイアログではなく、A3「リーグ表を作成する」ボタンから開く生成選択ダイアログ（下記A3の節を参照）内に警告文言をインライン表示する形で確認を行う。

### 共通エラー・制限表示（ブロック系ルール）

登録済みデータの存在や大会ステータスによって編集・削除がブロックされる場合（要件定義書 2.1, 3.2, 3.3参照）、対象のボタンを disabled にし、理由をツールチップまたは注記で表示する。

例：「試合結果が登録されているため、セット数は変更できません」「大会が終了しているため変更できません」「閲覧モードのため変更できません」

閲覧モード（要件定義書2.3）でログインしている場合も同様に、登録・編集・削除・生成・試合結果入力・バックアップ作成・リストアなど書き込みを伴うボタンはすべてdisabledにする（理由は「閲覧モードのため変更（実行）できません」）。共通ヘッダーには「閲覧モード」であることを示すバッジを表示する。書き込み系API Route Handlerも、閲覧モードのセッションからの呼び出しをAPIレベルで拒否する（403）。

## A1. ログイン画面

### 概要
環境変数でシードされた単一の管理者アカウントでログインする。サインアップ画面は設けない。ログインID・パスワードの変更も、ログイン前の本画面からダイアログで行う（詳細は下記「ログイン情報の変更」を参照）。ID・パスワードなしで管理者向け画面を読み取り専用（書き込み不可）で利用できる「閲覧モード」ボタンも用意する（要件定義書2.3参照）。

### 表示・入力項目

| 項目 | 種別 | 必須 | 備考 |
|---|---|---|---|
| ID | テキスト入力 | ◯ | |
| パスワード | パスワード入力（マスク） | ◯ | 最低8文字 |

### 操作

| 操作 | 内容 |
|---|---|
| ログインボタン | 認証成功時は[A2 大会一覧画面]へ遷移。失敗時はエラーメッセージ「IDまたはパスワードが正しくありません」を表示 |
| 閲覧モードで見るボタン | ID・パスワードの入力なしで、読み取り専用（書き込み不可）のセッションを発行し[A2 大会一覧画面]へ遷移する。ボタン下に「※閲覧モードでは、編集・バックアップ・リストアなどの書き込み操作はできません」と注記する |
| ログイン情報を変更するボタン | 「ログイン情報の変更」ダイアログを開く |

### 遷移先
- ログイン成功 → A2 大会一覧画面
- 閲覧モードで見る → A2 大会一覧画面（閲覧モード）

### ログイン情報の変更

管理者アカウントのログインID・パスワードを変更する。初期状態ではシードされた1組のID・パスワードが設定されており、本機能でその後いつでも変更できる。未ログイン状態（セッションなし）から実行できる操作のため、セッションの代わりに現在のID・パスワードの入力を本人確認として要求する。

ダイアログの横幅は、本人確認の説明文（「本人確認のため、現在のIDとパスワードを入力してください。」）が折り返されずに1行で表示できる幅を確保する。

#### 入力項目

| 項目 | 必須 | 条件 | 入力内容 |
|---|---|---|---|
| 現在のID | ◯ | | テキスト |
| 現在のパスワード | ◯ | | パスワード入力（マスク） |
| 新しいID | ◯ | | テキスト |
| 新しいパスワード | ◯ | | 最低8文字 |

#### 操作

| 操作 | 内容 |
|---|---|
| 変更するボタン | 現在のID・パスワードが一致する場合のみ、新しいID・パスワードで上書きする。成功時は「変更しました」、現在のID・パスワードが一致しない場合はエラーメッセージ「現在のIDまたはパスワードが正しくありません」を表示する |
| 閉じるボタン | ダイアログを閉じる |

## A3. 大会情報画面

### 概要
大会名・開催日・開催場所と、有効化するカテゴリ（A〜J）を登録・編集する（要件定義書3.1）。大会（保存済み）に対しては、本画面がタブ切り替えの起点となり、大会ステータスの切り替え・リーグ表等の一括生成・参加者向け閲覧URLの確認もここで行う。

新規作成時（大会未保存の間）は、タブ・ステータス表示・生成系ボタン・参加者向けURLは表示しない（保存して大会IDが発行されて初めて利用可能になる）。

本画面には大会削除ボタンは設けない（大会の削除は[A2 大会一覧画面]の行内削除ボタンからのみ行う）。

大会情報タブの保存ボタン・キャンセルボタンは、設定エリア（入力フォーム）の上部に配置する。新規作成時も同様に、フォーム最上部に保存・キャンセルボタンを配置する（キャンセルボタンは入力内容を破棄して[A2 大会一覧画面]へ戻る。編集時のキャンセルボタンは保存済みの内容にフォームをリセットする）。

### 入力項目

必須項目（大会名・開催日・開催場所・カテゴリA名称）はラベルに赤色の「*」マークを付し、未入力のまま保存しようとした場合は保存を拒否する（ブラウザの入力必須チェックで保存をブロックする）。大会名・開催場所の入力欄は、全角50文字を横スクロールなしで表示できる幅を確保する。大会名・開催場所・カテゴリ名称の各ラベルには「（最大n文字）」の形式で最大文字数を併記する。

| 項目 | 必須 | 条件 | 入力内容 |
|---|---|---|---|
| 大会名 | ◯ | | テキスト、MAX全角50文字 |
| 開催日 | ◯ | | カレンダー入力、デフォルト登録日 |
| 開催場所 | ◯ | | テキスト、MAX全角50文字 |
| カテゴリA 名称 | ◯ | | テキスト、MAX全角25文字 |
| カテゴリB〜J 有効化 | | チェックボックス | チェック時に名称入力欄を表示 |
| カテゴリB〜J 名称 | | 有効化時 | テキスト、MAX全角25文字 |

### バリデーション

- 同一大会内でカテゴリ名の重複は禁止（エラー表示）。
- 既に競技情報または選手(チーム)情報が登録済みのカテゴリは、チェックを外せない（チェックボックスをdisabledにし「登録済みのデータがあるため無効化できません」を表示）。
- 登録済みデータがなく無効化（チェックを外す）できるカテゴリについて、チェックを外して保存すると、そのカテゴリの競技情報設定は実質的に削除される（競技情報登録画面（A4）に専用の削除ボタンは設けない。詳細はA4の節を参照）。
- 大会ステータスが「終了」の場合、全項目を編集不可（フォーム全体をdisabledにし、設定エリア下部に「大会が終了しているため変更できません」を表示）。

### 表示項目（保存済みの大会を開いた場合）

| 項目 | 内容 |
|---|---|
| ステータス | 「進行中」または「終了」のバッジ表示 |
| 参加者向け閲覧URL | `/t/:tournamentId` の絶対URLを表示し、コピーボタンを設置 |

### ステータス別のボタン構成

大会ステータスに応じて、以下の2セットをこの順序で表示する（削除ボタンはいずれの状態にも表示しない）。本ボタン群はA3だけでなく、A4・A5でも共通タブの直上の同じ位置に表示する（詳細は「共通仕様」の「共通ヘッダー」を参照）。

| ステータス | ボタン（表示順） |
|---|---|
| 進行中（管理者） | 「リーグ表を作成する」→「大会を開催する」→「大会を終了する」 |
| 進行中（閲覧モード） | 「大会を閲覧する」（有効）→「大会を終了する」（常にdisabled） |
| 終了 | 「大会を閲覧する」→「大会を再開する」 |

閲覧モード（要件定義書2.3）でログイン中、かつ大会ステータスが「進行中」の場合は、書き込みを伴う「リーグ表を作成する」「大会を開催する」ボタンを表示せず、終了済みの大会と同様に「大会を閲覧する」（有効）・「大会を終了する」（常にdisabled）の2ボタンのみを表示する。

#### 「リーグ表を作成する」ボタン（進行中のみ表示）

- クリックすると、生成選択ダイアログ（下記）が開く。
- ダイアログで選択したカテゴリについてのみ、リーグ表・試合順・審判順を一括で自動生成する（各カテゴリの生成条件は要件定義書3.4〜3.6に準拠）。実行後も本画面に留まる（A6へは遷移しない）。
- 生成単位はカテゴリのみとする（コート単位では選択できない）。同一カテゴリ内の自動選択の選手(チーム)は、カテゴリ内の全コートへまとめて振り分けられる一体の処理であるため、コート単位で個別に生成・再生成すると振り分け結果と矛盾が生じるためである（要件定義書3.4参照）。
- 条件（参加選手(チーム)数2以上、各コート2以上、登録選手(チーム)数が「コート数×1コート最大選手(チーム)数」以下、試合結果が未入力）を満たさない選択カテゴリがある場合は、そのカテゴリのみ生成をスキップし、条件を満たさなかった理由を含めてダイアログで詳しく表示する（下記「生成結果ダイアログ」参照）。満たしているカテゴリは生成を続行する。

##### 生成選択ダイアログ

- 「リーグ表を作成する」ボタンをクリックすると開く。大会内の有効カテゴリを、「カテゴリC：上級」のようなラベルのチェックボックス一覧として表示する（コート単位の内訳は表示しない）。
- デフォルトはすべて未チェックとする。
- 「全てチェックする」「全てのチェックを外す」ボタンを設け、一括でチェック状態を切り替えられるようにする。
- チェックした対象の中に既に生成済み（再生成になる）ものが含まれる場合、「選択した対象の中に生成済みのものが含まれます。現在の内容は上書きされます。」という警告文言をダイアログ内にインライン表示する（独立した確認ダイアログは別途表示しない）。
- 「作成する」ボタンは、1件もチェックされていない場合はdisabledにする。クリックすると、チェックされたカテゴリのみ生成（または再生成）を実行し、成功した場合はダイアログを閉じて同画面に留まる。
- APIがエラーを返した場合（大会終了・対象不在等）は、ダイアログを閉じずにダイアログ内へエラーメッセージを赤字表示する（何も起きなかったように見えるまま処理が失敗することを防ぐため）。
- 「キャンセル」ボタンでダイアログを閉じ、何も実行しない。

##### 生成結果ダイアログ

- 生成選択ダイアログで「作成する」を実行した結果、条件を満たさず生成をスキップしたカテゴリが1件以上ある場合、確認ダイアログボックスを表示する（エラーメッセージの1行表示ではなく、ダイアログボックスとする）。
- ダイアログには、生成済みカテゴリの一覧と、スキップしたカテゴリごとに「カテゴリ名：理由」の形式で詳細な理由を表示する。理由は「参加選手(チーム)数がn名のため作成できません（2名以上必要です）」「コートnの割当人数がn名のため作成できません（各コート2名以上必要です）」「想定を超える選手(チーム)が登録されています。競技情報のコート数、または、１コート最大選手(チーム)数を変更して下さい。」「試合結果が入力されています。試合結果を削除して下さい。」のように、どの条件を満たさなかったかを具体的に示す（後半2件は改行を含めて表示する）。
- 「閉じる」ボタンでダイアログを閉じる。

#### 「大会を開催する」ボタン（進行中のみ表示）

- 大会内の有効カテゴリのうち1つでも生成済みであれば活性化する（全カテゴリが未生成の場合のみdisabled）。
- クリックすると、再生成は行わず現在のデータのまま[A6 試合・順位表画面]を開く（カテゴリが複数ある場合は先頭のカテゴリのA6を開き、他カテゴリへはカテゴリタブから移動する）。確認ダイアログは表示しない。

#### 「大会を終了する」ボタン（進行中のみ表示）

- 確認ダイアログの上で、大会ステータスを「終了」に切り替える（同画面に留まる）。

#### 「大会を閲覧する」ボタン（終了、または閲覧モードで進行中の場合に表示）

- 現在のデータのまま[A6 試合・順位表画面]を開く（閲覧専用）。確認ダイアログは表示しない。
- 大会内のどのカテゴリも1件もリーグ表が生成されていない場合は、クリックしても画面遷移せず、エラーダイアログ（タイトル「大会を閲覧できません」、本文「まだリーグ表が生成されていません。大会情報画面の「リーグ表を作成する」から生成してください。」）を表示する。「閉じる」ボタンで閉じる（想定外の改行が入らないようダイアログ幅を確保する）。

#### 「大会を再開する」ボタン（終了のみ表示）

- 確認ダイアログなしで、大会ステータスを「進行中」に戻す（同画面に留まる）。

## A4. 競技情報登録・編集画面

### 概要
カテゴリ単位でセット数・順位決定方式・勝点・コート数等を登録・編集する（要件定義書3.2）。要件定義書上「カテゴリ別」の機能であるため、カテゴリタブで対象カテゴリを切り替える（コートタブは不要）。大会ステータス別のボタン群（「リーグ表を作成する」等）も共通タブの直上に表示する（詳細は「共通仕様」の「共通ヘッダー」を参照）。

保存ボタンは、設定エリア（カテゴリタブの下の入力フォーム）の上部に配置する。本画面に削除ボタンは設けない。競技情報（カテゴリのルール設定）自体の削除は、大会情報画面（A3）のカテゴリチェックボックスを外して保存することで行う（詳細はA3の節「バリデーション」を参照）。

### 入力項目

| 項目 | 必須 | 条件 | 入力内容 |
|---|---|---|---|
| セット数 | ◯ | | 数値、範囲1〜5、デフォルト1 |
| 順位決定方式 | ◯ | | 選択：勝敗方式 / 勝点方式、デフォルト勝敗方式 |
| 勝利勝点 | | 勝点方式時のみ編集可 | 数値、範囲0〜5、デフォルト3 |
| 引分勝点 | | 勝点方式時のみ編集可 | 数値、範囲0〜5、デフォルト1 |
| 敗北勝点 | | 勝点方式時のみ編集可 | 数値、範囲0〜5、デフォルト0 |
| コート数 | ◯ | | 数値、範囲1〜5、デフォルト1 |
| リーグ形式（単一リーグにするチェックボックス） | ◯ | コート数が2以上の場合のみ編集可 | チェックボックス、デフォルト未チェック（独立リーグ） |
| 1コート最大選手(チーム)数 | ◯ | 単一リーグの場合は編集不可 | 数値、範囲2〜10、デフォルト5 |

勝利勝点・引分勝点・敗北勝点は、順位決定方式の選択に関わらず常に表示する（非表示にはしない）。順位決定方式が「勝敗方式」の場合はこの3項目をdisabledにし、「勝点方式」を選択したときのみ編集可能にする。

「単一リーグにする」チェックボックスは、コート数が1の間はdisabledかつ未チェック（独立リーグ）固定とする。コート数を1に戻した場合、チェック状態に関わらず保存時は独立リーグとして扱う。ラベルは「単一リーグ」の短い表記とし、横にℹ️アイコンボタンを配置する。ボタンを押すと、チェックボックスの意味（「チェックすると、複数コートにまたがる1つのリーグとして試合順・順位表を生成します（コート数が2以上の場合のみ設定できます）。」）を説明するダイアログを表示する（想定外の改行が入らないようダイアログ幅を確保する）。

「1コート最大選手(チーム)数」は、リーグ形式が単一リーグの場合は編集不可（disabled）にする。単一リーグはコート毎の独立した定員を持たないため（要件定義書3.2・3.4参照）。

### バリデーション

- 勝利勝点 > 引分勝点 > 敗北勝点。
- 1コート最大選手(チーム)数は2以上必須（コート数に関わらず常に2以上）。
- 試合結果が1件でも登録済みの場合、全項目を編集不可（フォーム全体をdisabledにし「試合結果が登録されているため変更できません」を表示）。
- 選手(チーム)または試合結果が1件でも登録済みの場合、大会情報画面（A3）でこのカテゴリのチェックを外すこと（＝削除）はできない。
- 大会ステータスが「終了」の場合、全項目を編集不可（フォーム全体をdisabledにし「大会が終了しているため変更できません」を表示）。

### 操作

| 操作 | 内容 |
|---|---|
| 保存ボタン | バリデーション成功時に保存（同じ画面に留まる） |
| カテゴリタブ | 編集対象のカテゴリを切り替える |
| 共通タブ | [大会情報(A3)][選手(チーム)(A5)]へ自由に移動できる |

## A5. 選手(チーム)情報画面

### 概要
大会全体を横断して選手(チーム)の一覧表示・登録・編集・削除を行う（要件定義書3.3）。要件定義書上、選手(チーム)情報登録は「カテゴリ別」の機能ではなく、登録フォーム内でカテゴリを選択する仕様のため、本画面にカテゴリタブは設けない。一覧にはカテゴリ列を表示する。大会ステータス別のボタン群（「リーグ表を作成する」等）も共通タブの直上に表示する（詳細は「共通仕様」の「共通ヘッダー」を参照）。

一覧の上部に「選手(チーム)一覧」等のタイトル見出しは表示しない。新規登録・編集・削除は画面内の下書きとして即座に一覧表示へ反映され、大会情報タブ（A3）と同様にフォーム最上部に配置した保存ボタンを押した時点でまとめてサーバーへ反映する（保存するまでは変更が確定しない）。

### 一覧表示項目

| 項目 | 内容 |
|---|---|
| 選手(チーム)名 | |
| 所属 | 任意項目のため空欄もあり得る |
| カテゴリ | 所属するカテゴリ名 |
| コート選択 | 自動／手動（対象カテゴリのコート数が2以上かつ独立リーグの場合のみ値が入る） |
| コート番号 | 手動選択時のみ |
| 操作 | 編集・削除ボタン |

各列の幅は、その項目の定義上の最大文字数に合わせて固定する（選手(チーム)名・所属は全角10文字分、カテゴリはカテゴリ名の全角25文字分＋「カテゴリX：」表記分、コート選択・コート番号は値の最大文字数分）。

一覧の表題（列見出し）をクリックすると、その列を基準に昇順／降順でソートできる（再クリックで昇順→降順→ソート解除の順にトグルする）。

### 登録・編集フォーム項目

| 項目 | 必須 | 条件 | 入力内容 |

| 選手(チーム)名 | ◯ | | テキスト、MAX全角10文字 |
| 所属 | | | テキスト、MAX全角10文字（任意） |
| カテゴリ | ◯ | | 選択：大会情報で有効なカテゴリ、デフォルト：カテゴリA |
| コート選択 | | 選択したカテゴリのコート数が2以上かつ独立リーグの場合 | 選択：自動／手動 |

選択したカテゴリが単一リーグの場合、コート選択・コート番号の欄は表示しない（選手(チーム)は特定の物理コートに固定されず、リーグ表自動生成時に試合単位で自動的にコートへ振り分けられるため）。

カテゴリ選択コンボボックスの横幅は、全角40文字分で固定し、選択肢が折り返されないようにする。一覧のカテゴリ絞り込みコンボボックスも同じ幅とする。新規登録・編集フォーム（モーダル）の横幅は、このコンボボックス幅がはみ出さないよう十分な余白を確保する。

### バリデーション

- 選手(チーム)名は同一大会・同一カテゴリ内で重複不可（別カテゴリでは同名登録可）。
- 手動選択時、同一カテゴリ・同一コート番号の選手(チーム)数 ≦ そのカテゴリの1コート最大選手(チーム)数。
- カテゴリ内の登録選手(チーム)数合計は、そのカテゴリの「コート数 × 1コート最大選手(チーム)数」を超えられない（上限到達時は該当カテゴリへの新規登録をエラーにする）。

## A6. 試合・順位表画面

### 概要
カテゴリ単位でリーグ表・試合順・審判順を閲覧し、自動集計された勝敗表（順位表）を同じ画面内で確認する（要件定義書3.4〜3.9統合）。カテゴリタブで対象カテゴリを切り替える。表示構成はカテゴリのリーグ形式（独立リーグ／単一リーグ、A4参照）によって異なる。

- 独立リーグ（コート数1、またはコート数2以上かつ独立リーグ）：コート数が2以上の場合はさらにコートタブを表示する。1つのコートが1つの独立したリーグ（総当たり戦のまとまり）であるため、対戦カード・試合順・審判順・勝敗表（順位表）をコート単位でまとめて表示する。
- 単一リーグ（コート数2以上かつ単一リーグ）：コートタブは表示しない。リーグ表・勝敗表（順位表）はカテゴリ全体で1つに統合して表示する。試合順表は1つの表の中で「試合順」列をコート間で共有し、コート毎に「対戦カードー審判ー結果」の3列をまとめて横に並べる。同一時間帯（同じ「試合順」番号）に並行開催する試合が同一行に揃って見えるようにする（詳細は下記「試合順表のレイアウト仕様」）。

リーグ表・試合順・審判順の生成・再生成は行わない（大会情報画面（A3）の「リーグ表を作成する」ボタンに一元化しており、本画面には生成・再生成ボタンを設けない）。本画面への入口は、A3の「大会開催」ボタン（全カテゴリ生成済みの場合）と「大会を閲覧する」ボタン（大会ステータス＝終了の場合）の2つのみであり、共通タブには含めない（詳細は「共通仕様」を参照）。本画面を開いた後は、共通タブ（[大会情報(A3)][競技情報(A4)][選手(チーム)(A5)]）から他画面へ移動できる。

画面上部は、A3（大会情報画面）と同様の大会名ヘッダー（大会名の改行表示・ステータスバッジ・開催日/開催場所・参加者向け閲覧URL）を表示する。続けて共通タブ（[大会情報][競技情報][選手(チーム)]）を表示するが、A6自身はこのタブセットに含まれないため、どのタブもアクティブ状態にはしない。

本画面の表示順は上から「リーグ表・勝敗表（順位表）」→「試合順表」の順とする。

### 表示項目（未生成カテゴリを開いた場合）

まだリーグ表が生成されていない旨のメッセージと、大会情報画面（A3）へ戻るリンクのみを表示する（生成操作はA3でのみ行うため）。

### 表示項目（生成後。独立リーグはコートごと、単一リーグはカテゴリ全体で1組）

| 項目 | 内容 |
|---|---|
| リーグ表・勝敗表（順位表） | 総当たり対戦結果と勝敗表の集計を1つの表にまとめたマス目形式（詳細は下記）。行・列はリーグ表自動生成時にランダムに決定した順序（登録順ではない）で固定表示し、再生成するまで変わらない。順位による並べ替えは行わない |
| 試合順表 | 試合順・対戦カード・審判・結果（未入力ボタン、または入力済みの場合は「入力済」ボタン＋「削除」ボタン）を1行ずつ表示する一覧。全試合を1つの表にまとめて表示する（列分割は行わない。詳細は下記）。単一リーグの場合は1つの表の中で試合順列を共有し、コート毎に列をまとめて表示する |
| タイ時のミニリーグ | 3者以上が同成績でタイした場合、タイした者同士の対戦結果のみで再集計した結果を表示 |
| じゃんけん待ちフラグ | 対戦結果でも決着しない組について表示 |

#### リーグ表・勝敗表（順位表）のマス目仕様

- 行・列はいずれも対象コートの選手(チーム)。各行・列の見出しは2行で表示し、1行目に所属、2行目に選手(チーム)名を表示し、両者の間を点線で区切る（所属が未登録の場合は1行目を空欄にする）。
- 列幅は固定とする（利用者によるドラッグ調整は行わない）。選手(チーム)名列は全角11文字分、それ以外の列（対戦マス・集計列・順位列）は全角6文字分で固定する。選手(チーム)名列の見出し・各行見出しとも、文字は上下中央・左右中央揃えで表示する。
- 対角線（同一選手(チーム)同士）は使用不可のマスとして、右下がりの斜線を表示してブロックする（入力・クリック不可）。
- 対角線以外の各マス（行×列）は、行の選手(チーム)から見た対戦結果を、左から「勝敗マーク・各セットの得点・セット取得数の要約」の順に表示する。左側の勝敗マーク（◯：勝ち、●：負け、ー：引分、未対戦は空欄）はやや大きめの文字、右側のセット取得数の要約（例「2-0」）もやや大きめ・下線・斜体の文字で表示する。中央の各セットの得点（例セット1「25-20」、セット2「18-25」。未入力セットは表示しない）は、セットごとに縦に並べて小さめの文字で表示する。セットスコアの編集はマスをクリックして開く結果入力ダイアログで行う。
- マスをクリックすると、その対戦の結果入力ダイアログが開く（詳細は下記）。大会ステータスが「終了」の場合はクリックしても閲覧専用ダイアログが開く。
- 表の右側に集計列を追加する：試合数、勝ち数、引分数、負け数、セット率、得点、失点、得点率、勝点（勝点方式の場合のみ）、順位。集計項目・算出式は要件定義書3.8に準拠する。
- 棄権列は設けない（不戦勝・棄権対応は将来対応要件、要件定義書5章）。

#### 試合順表のレイアウト仕様

- 独立リーグの場合：試合順（1試合目〜最終試合）を1つの表に縦一列で表示する（10試合ごとに列を分ける等の分割は行わない）。表が縦に長くなる場合は画面のスクロールで対応する。
- 単一リーグの場合：1つの表にまとめ、左端の「試合順」列をコート間で共有する。見出しは2段構成とし、1段目はコート毎に「コートN」をコート内3列（対戦カード・審判・結果）分の結合セルとして表示し、1段目の左端（試合順列の真上）は右上がりの対角線のみを表示する空セルとする。2段目は各コートの「対戦カード・審判・結果」見出しを繰り返す。同一時間帯に複数コートで並行開催する試合は同じ「試合順」番号の行に揃えて表示する。あるコートにその時間帯の試合がない場合は、当該コートの3列のみ「―」で埋める（試合順列・他コートの表示には影響しない）。
- 対戦カードは選手(チーム)名のみ（所属は表示しない）で表記する（例：「田中 - 渡辺」）。審判欄も同様の表記とする。対戦カードは常にリーグ表の上位（リーグ表の並び順が先）を左に記載する（例：リーグ表の並びがA・B・Cの場合、A-B、A-C、B-Cの順で表記し、C-Bのような逆順にはしない）。最初の試合はリーグ表の上位2者の対戦から開始する。
- 審判欄は、審判が割り当てられている場合は選手(チーム)名を表示し、割り当てられない場合（対戦カードの2者以外に候補がいない等）は赤字・太字で「運営スタッフ」と表示する（要件定義書3.6）。
- 各列の幅は固定とし、文字は上下中央・左右中央揃えで表示する（試合順列は全角6文字分、対戦カード列は全角25文字分、審判列は全角11文字分）。対戦カードの「-」部分は、各選手(チーム)名の文字数に関わらず列の中央に固定表示する。
- 行（独立リーグ）、または対戦カード・審判セル（単一リーグ、試合が割り当てられたコート分のみ）をクリックすると、その試合の結果入力ダイアログが開く（マスのクリックと同じダイアログを共有する）。単一リーグで試合が割り当てられていないコートの「―」表示セルはクリックできない。
- 結果列は、未入力の場合は「未入力」ボタンを表示する。押下すると（行クリックと同様に）結果入力ダイアログを開く。
- 入力済みの場合は「入力済」ボタンと「削除」ボタンを横並びで表示する。「入力済」ボタンは結果入力ダイアログを開く（修正用）。「削除」ボタンは（行クリックとは独立して）確認ダイアログなしで即座に試合結果を削除し未入力状態に戻す。削除後は勝敗表（順位表）を自動的に再集計する。「入力済」ボタンと「削除」ボタンは、意図せず押し間違えないよう塗り/枠線を反転させた対照的な見た目にする（「入力済」は塗りつぶし、「削除」は枠線のみ）。

#### 結果入力ダイアログ仕様（要件定義書3.7）

マス、または試合順表の行をクリックすると、1試合分のセットスコアを入力するダイアログが開く（A8画面への遷移は行わない。モーダル操作のみで完結する）。

- ダイアログタイトルは「試合結果の入力」の固定文言とする（対戦する選手(チーム)名は表側の見出しに表示する）。
- 横軸（列）に選手(チーム)名（所属は表示しない）を2名分、縦軸（行）に競技情報のセット数分のセット番号を「1セット」「2セット」のように表示する、シンプルな入力表のみとする（試合全体の勝敗サマリ文等の付加情報は表示しない）。
- 選手(チーム)名列の幅は固定とする（利用者によるドラッグ調整は行わない）。全角11文字分で固定し、文字は上下中央・左右中央揃えで表示する。
- 各セット行の入力欄は、選手(チーム)ごとに点数入力欄（範囲0〜999）を1つずつ並べる。入力値に応じて「◯（勝ち）」「ー（引分）」のマークを各選手(チーム)側に自動表示する（要件定義書3.7の例に準拠）。
- ダイアログの幅は、セット番号（「1セット」等）やスコア入力欄が折り返されず1行で表示できる幅を確保する（表の内容に合わせて可変とする）。
- 保存すると、同じダイアログを閉じてA6画面に留まり、リーグ表・勝敗表を自動再集計する。保存済みの結果は再度マス（または試合順行）をクリックして開き、修正できる。
- 途中で勝敗が決した場合、残りのセットは入力不要（空欄のまま保存可）。
- 複数端末からの同時保存は排他制御せず、最後に保存した内容で上書きする。
- 大会ステータスが「終了」の場合、すべての入力欄をdisabledにし、保存ボタンを非表示にした閲覧専用ダイアログとして開く。

### バリデーション（生成時）

生成自体は大会情報画面（A3）の「リーグ表を作成する」ボタンで行う。条件（参加選手(チーム)数2以上、試合結果が未入力。独立リーグの場合はさらに各コート2以上・登録選手(チーム)数が「コート数×1コート最大選手(チーム)数」以下）を満たさないカテゴリは生成がスキップされ、A3側に警告を表示する（詳細はA3の節を参照）。

### 大会ステータスが「終了」の場合

- 大会一覧（A2）でステータス「終了」の大会を選択するとA3（閲覧専用）へ遷移し、A3の「大会を閲覧する」ボタンから本画面を開く。
- 最終順位の手動確定ボタンはdisabledにする。
- マス・試合順表の行クリックで結果入力ダイアログは開けるが、すべての入力欄がdisabledの閲覧専用表示となる。

### 操作

| 操作 | 内容 |
|---|---|
| カテゴリタブ | 対象カテゴリを切り替える |
| コートタブ | 対象コートを切り替える（コート数2以上かつ独立リーグの場合のみ表示。単一リーグの場合は表示しない） |

## A8. バックアップ・リストア画面

### 概要
全データのJSONエクスポート（手動バックアップ）と、エクスポート済みJSONからの復元（リストア）を行う（要件定義書4章）。タイトルは戻りリンクの下に改行して表示する（スタック表示）。

バックアップの作成・復元はいずれも実際のファイル操作であり、プレースホルダーではない。手動・ログアウト時いずれのバックアップも実際にJSONファイルを生成してサーバー側にのみ保存する（個別ダウンロードは提供しない。復元はバックアップ履歴からの選択で行うため、ダウンロード→再アップロードという手順を必要としない）。自動（無条件）のバックアップは行わない。ログアウト時のバックアップも、ログアウト確認ダイアログで管理者が「バックアップする」を選んだ場合のみ作成される（詳細は「共通仕様」のログアウト操作を参照）。

バックアップの保持数は20件を上限とする。新規作成により20件を超えた場合、履歴・ファイルともに最も作成日時が古いものから削除する。

ログイン情報（ID・パスワード）の変更は、本画面ではなく[A1 ログイン画面]のダイアログから行う（詳細はA1の節を参照）。

### 表示項目

| 項目 | 内容 |
|---|---|
| バックアップ履歴 | 復元対象を選ぶラジオボタン、作成日時（秒単位）、作成契機（手動／ログアウト） |
| 期間フィルタ | 作成日時の期間（開始日・終了日）でバックアップ履歴を絞り込む表示フィルタ |

### 操作

リストアは、1. バックアップデータ（作成日時）の選択、2. 復元ボタン押下、3. 復元実行最終確認（ダイアログ）、の3段階の操作順で行う。

| 操作 | 内容 |
|---|---|
| 今すぐバックアップボタン | 全テーブルをJSONエクスポートし、履歴に追加する（バックアップ履歴の一覧より上に配置） |
| 期間フィルタ（開始日・終了日） | 入力した期間でバックアップ履歴を絞り込む（ページ遷移やURLは変化しない） |
| バックアップ履歴の選択欄 | 一覧の各行にラジオボタンを設け、復元対象とする1件（作成日時）を選択する |
| データ復元（リストア）欄 | バックアップ履歴の一覧より下に配置する。操作説明「※バックアップデータ選択後、復元ボタンを押して下さい」と復元ボタンを表示する。未選択時は復元ボタンをdisabledにする。復元ボタン押下で確認ダイアログを開き、ダイアログ内に選択したバックアップの作成日時と実行注意（全データ上書きの警告）を表示し、承認後に復元を実行する |
