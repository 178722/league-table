# 用語集

## 目的

本ドキュメントは `要件定義書.md` に登場する用語を整理し、`画面仕様書.md` / `データベース仕様.md` / `API仕様.md` などで用語の表記や命名がブレないようにするためのものです。

- 定義の一次情報源は `要件定義書.md` です。本ドキュメントと齟齬がある場合は要件定義書を優先してください。
- 新しい用語を追加・変更した場合は、本ドキュメントも合わせて更新してください。

## 用語一覧

| 用語 | 英語表記案 | 定義 | 備考・制約 |

| 大会 | Tournament | 運営者が開催するイベント全体の単位。大会名・開催日・開催場所・カテゴリを持つ | 大会名/開催場所は全角50文字以内。削除時は紐づく競技情報・選手(チーム)情報・試合・試合結果を連鎖削除する。参加者向け閲覧URLは大会単位で発行する。「進行中」「終了」のステータスを持ち（デフォルト進行中）、管理者が手動で切替可能。「終了」中は大会情報・競技情報・選手(チーム)情報の編集、試合結果の入力・修正が不可 |

| 物理コート | Physical Court | 独立リーグにおいて選手(チーム)を実際に割り当てる会場区画そのもの。カテゴリごとに独立しており、他カテゴリとのコート資源の競合は考慮しない | [[コート]]はカテゴリ単位の設定項目（コート数等）を指す語として使う一方、「物理コート」は実際の会場区画を指す語として3.4で使われる。単一リーグの場合、選手(チーム)は特定の物理コートに固定されず、試合のみを複数の物理コートへ振り分けて並行開催する（3.4参照） |
| 独立リーグ／単一リーグ | Independent League / Single League | 競技情報登録のコート数が2以上の場合に選べるリーグ形式（デフォルト：独立リーグ）。独立リーグはコート毎に別々の総当たり戦として扱い、単一リーグは複数コートにまたがる1つの総当たり戦として扱う | 単一リーグでは、選手(チーム)情報登録のコート選択・コート番号は使用せず、リーグ表・勝敗表（順位表）はカテゴリ全体で1つに統合する。コート数が1の場合は常に独立リーグ扱い |

| リーグ表 | League Table | カテゴリ単位（独立リーグの場合はさらにコート単位）で自動生成される総当たり対戦表 | 組合せ数は N×(N-1)÷2。試合順・審判順と常に一括で生成・再生成する（個別再生成は不可） |
| 試合 | Match | リーグ表上の1対戦 | |
| 対戦／対戦カード | Matchup / Matchup Card | どの選手(チーム)同士が対戦するかという組合せ、またはそれを表す1件の表示単位 | リーグ表（行・列）・試合順表の対戦カードの並び順は、リーグ表自動生成の実行時点でランダムに決定する（3.4参照、並び順自体は[[表示順]]を参照）。審判順自動生成は対戦カードを確定してから審判を割り当てる（試合＞審判の優先順位、3.6参照） |

### 生成・運用系の用語

| 用語 | 英語表記案 | 定義 | 備考・制約 |
|---|---|---|---|
| 試合順 | Match Order | 試合を実施する順序。自動生成される | 同一チームの連戦回避、コート数考慮、休憩時間の均等化が条件。単一リーグの場合、同一時間帯に複数コートで並行開催する試合は同じ試合順番号を共有する |
| ラウンド | Round | 単一リーグの試合順自動生成において、総当たり組合せを対戦が重複しない単位で区切った1巡分 | ラウンドをまたがずにコート数ぶんずつ時間帯（試合順）へ詰める（3.5参照） |
| 審判順 | Referee Order | 各試合の審判担当順。試合順の表に付加する形で自動生成される | 同一チームの連続審判回避、担当回数の均等化が条件。対戦カードを確定してから審判を割り当てる（試合＞審判の優先順位）。独立リーグは同一コート内、単一リーグは同一時間帯に他コートで試合していない同一カテゴリの選手(チーム)から選出する。候補がいない場合は[[運営スタッフ]]とする |
| 運営スタッフ | Staff Referee Fallback | 審判を割り当てられる選手(チーム)がいない場合の表示上のフォールバック値 | 対戦カードの2者以外に審判候補がいない場合（独立リーグで同一コートの参加者が2名のみ、単一リーグで全員が同時刻に試合中等）に、審判欄へ赤字で表示する。単一リーグで同一時間帯の複数コートが同時にこの状態になることは許容し、同一時間帯に複数の「運営スタッフ」表示が並んでもよい |
| セット | Set | 1試合内の勝敗を決める区切り単位 | カテゴリごとに1〜5セットで設定 |
| 試合結果 | Match Result | セットごとのスコア入力と、その結果（勝/分/敗） | スコア範囲0〜999。高得点側が勝(◯)、同点が分(ー)、負けは空欄。途中で勝敗が決した場合、残りセットは入力不要（未入力セットは集計対象外）。登録後の修正可能で、修正時は勝敗表を自動再集計する。複数端末からの同時編集は排他制御せず、最後の保存を優先する |

### 順位決定関連の用語

| 用語 | 英語表記案 | 定義 | 備考・制約 |
|---|---|---|---|
| 順位決定方式 | Ranking Method | 「勝敗方式」または「勝点方式」のいずれか。カテゴリ単位で設定 | |
| 勝利勝点 / 引分勝点 / 敗北勝点 | Win Points / Draw Points / Loss Points | 勝点方式を選んだ場合に、競技情報登録で設定する1試合あたりの配点ルール | 範囲0〜5。勝利勝点 > 引分勝点 > 敗北勝点 の制約あり |
| 勝ち数 / 引分数 / 負け数 | Wins / Draws / Losses | 選手(チーム)の全試合を集計した勝敗数。1試合（複数セット）は、勝ちセット数の多い方を試合の勝ちとし、同数の場合は引分とする | 自動計算の結果 |
| 得セット数 / 失セット数 / セット率 | Sets Won / Sets Lost / Set Rate | 全試合を通じて獲得/喪失したセット数の合計、およびセット率＝得セット数÷失セット数 | 自動計算の結果。失セット数0（無敗）かつ得セット数>0の場合は無限大（画面表示は「MAX」）、両方0（試合未実施）の場合は0として扱う |
| 得点 / 失点 / 得点率 | Points For / Points Against / Point Rate | 全試合を通じて獲得/喪失したスコアの合計、および得点率＝得点÷失点 | ⚠️「得点」という語は試合結果入力時のセットスコアとも混同しやすい。下記「表記ゆれ・曖昧語への注意」参照。得点率の分母0の扱いはセット率と同様 |
| 勝点 | Points | 勝点方式において、勝利勝点/引分勝点/敗北勝点を全試合分合計した値。順位決定の第一基準 | ⚠️「勝利勝点」等（配点ルール）とは別の集計値。下記注意参照 |
| 最終順位 | Final Rank | 順位決定ロジックを経て確定したカテゴリ内順位。直接対決でも決着しない場合はじゃんけん（システム外）の結果を管理者が手動で順位に反映する | 勝敗方式: 勝敗数→セット率→得点率→直接対決→じゃんけんの順。勝点方式: 勝点→セット率→得点率→直接対決→じゃんけんの順。⚠️手動確定は勝敗表への直接反映のみで確定状態自体は記憶しないため、同一コート・カテゴリの別の試合結果が保存されるたびに勝敗表は丸ごと自動再集計され、タイ条件が解消していなければ再び[[じゃんけん待ち]]に戻る（恒久的な上書きではない） |
| 直接対決 | Head-to-head | 同成績の選手(チーム)間での対戦結果による順位決定基準 | 3者以上が同成績でタイした場合は、タイした者同士の試合結果のみを抽出した[[ミニリーグ]]として再集計する |
| ミニリーグ | Mini-league | 直接対決でも決着しない3者以上のタイについて、タイした者同士の試合結果のみを抽出して勝敗・セット率・得点率等を再集計する際の、対象を絞った仮想的なリーグ表 | [[直接対決]]の判定時にのみ発生する一時的な集計単位であり、画面上に専用の表やIDは持たない |
| じゃんけん | Rock-Paper-Scissors | 直接対決でも決着しない場合の最終的な順位決定手段 | システム外（参加者同士）で行い、管理者が結果を手動で最終順位へ反映する |
| じゃんけん待ち | Janken Pending | `StandingRow.jankenPending`。直接対決でも決着しない組に立つフラグ。画面（A6）では「じゃんけん待ちフラグ」として表示する | [[最終順位]]の手動確定でフラグが解除されるが、確定状態は記憶されないため、同一コート・カテゴリの別の試合結果が保存されると勝敗表の再集計により再び立つことがある |

### 役割

| 用語 | 英語表記案 | 定義 | 備考・制約 |
|---|---|---|---|

## 表記ゆれ・曖昧語への注意

- **「得点」の多義性**: 要件定義書内で「得点」は (a) 試合結果入力時のセットごとのスコア（0〜999の数値）と、(b) 全試合を集計したランキング表の「得点」列の2つの意味で使われている。実装（`src/types/domain.ts`）では両者を明確に区別し、(a) は`SetScore.scoreA`/`scoreB`、(b) は`StandingRow.pointsFor`/`pointsAgainst`という別フィールド名を採用している（データベース仕様.md参照）。
- **「勝点」の多義性**: 「勝利勝点・引分勝点・敗北勝点」は競技情報登録時に設定する**配点ルール**であるのに対し、「勝点」単体は結果集計後の**合計スコア**を指す。実装ではルール設定値を`CategorySettings.winPoints`/`drawPoints`/`losePoints`、集計値を`StandingRow.points`という別フィールドとして区別している（データベース仕様.md参照）。
- **「選手(チーム)」の表記**: 要件定義書では個人戦・団体戦どちらにも対応するため「選手(チーム)」と併記されている。画面文言ではこの表記をそのまま使ってよいが、DB/APIの内部命名では `player_team` または `entrant` のような統一名を検討する。
- **「競技情報」と「カテゴリ」**: 要件定義書では見出しとして「競技情報登録」、フィールド名として「カテゴリA〜J」が使われており、両者はほぼ同じ対象を指す。本用語集では「競技情報 / カテゴリ」として併記しているが、DB設計では `category` テーブル1つに統一することを推奨する。
