# 結合テストケース一覧

## 目的

本ドキュメントは、`CLAUDE.md` のテスト方針に基づき、API Routes・DB（ファイルベースJSONストア）・画面間の連携など、複数コンポーネントを跨いだ振る舞いを検証する結合テストケースを列挙する。

- 本書はテストケースの仕様である。実行可能なテストコードは `tests/integration/*.spec.ts`（Playwright。開発サーバーに対して実際の画面操作・API呼び出しを行う結合テスト）として実装している。ファイルベースJSONストアは本番の正式なデータ永続化方式として確定しており（CLAUDE.md参照）、クラウドDBへの置き換えは行わない方針のため、本書のテスト実装方式も今後変更しない。
- 単体で閉じるコアロジックの検証は `docs/ユニットテスト.md` を参照。本書はそれらが組み合わさって正しく動作するかに焦点を当てる。
- 画面仕様・URL構成は `docs/画面仕様書.md`、画面IDは同書の「画面一覧」に準拠する。
- 実行コマンド: `npm run test:integration`（`playwright.config.ts`が開発サーバーを自動起動する）。

## 9. 一括生成のシナリオ拡充（`tests/integration/variations.spec.ts`）

上記1〜8章は機能要件ごとの代表的な1〜数シナリオを列挙したものだが、リーグ表自動生成（4章I-GEN-01/02相当）は「参加人数・順位決定方式・コート数・リーグ形式・セット数」の組合せによって経路が分岐するため、境界値・組合せのバリエーションを追加で広くカバーする回帰テスト群を`variations.spec.ts`に実装している（個別のNo採番はせず、`I-VAR-`接頭辞のテスト名で表す）。

- 成功系：参加人数N=2〜9、順位決定方式（勝敗方式／勝点方式、配点ルールも複数パターン）、コート数1〜3、独立リーグ／単一リーグ、セット数1〜5の組合せを変えた約20パターンで、生成後の総試合数がN×(N-1)÷2と一致することを検証する
- スキップ系：参加人数0名・1名、および独立リーグでコート間の人数配分が不均等になり1コートの割当人数が2名未満になるケース（同条件でも単一リーグなら生成に成功することと対比できるよう、成功系にも同一設定の単一リーグ版シナリオを用意している）で、理由付きのスキップダイアログが表示されることを検証する
