## 本書作成にあたっての対応

`docs/結合テスト.md` の精査、シナリオ拡充（`variations.spec.ts`の新規追加）、および結合テスト実施の過程で、以下の修正を行った。

### ドキュメントの精査・修正

1. **冒頭の目的欄・マッピング注記が、将来移行しない方針のPrisma/PostgreSQLへの置き換えを前提にした記述のままだった**（CLAUDE.mdは当該移行を「行わない方針として確定」と明記）→ ファイルベースJSONストアが本番の正式な方式であることを前提にした記述へ修正（I-AUTH-04の脚注についても同様に修正）。
2. **`tests/integration/single-league.spec.ts`に実装済みの`I-SGL-02`、`tests/integration/auth.spec.ts`に実装済みの`I-AUTH-03b`・`I-AUTH-07`が、ドキュメント上は未採番だった** → 各シナリオの内容に即した説明を付けて新規行として追加した。
3. **テストコード自身の表記ミス**：`lifecycle.spec.ts`のI-ST-04と`generation.spec.ts`のI-GEN-05が、実際には[A6]（試合・順位表画面）を検証しているにもかかわらずテストタイトルが「[A7]」になっていた（ドキュメント側は元々正しく[A6]と記載） → テストタイトルを[A6]に修正。

### 結合テスト実施後に判明したアプリケーションの実バグ修正

4. **`POST /api/tournaments/:id/generate`が、リクエストボディの「省略」と「JSONとして解釈できない（破損）」を区別せず、どちらも「全有効カテゴリを対象に生成」という既定動作にフォールバックしていた**。これは、選択していないカテゴリまで気づかれずに生成・上書きしてしまう実際のリスクがあるため、ボディが空でないのにJSONとして解釈できない場合は`400 VALIDATION_ERROR`を返すよう修正（`src/app/api/tournaments/[tournamentId]/generate/route.ts`）。あわせて、`GenerateSelectionDialog`（A3の生成選択ダイアログ）が生成失敗時にエラーメッセージを一切表示せずダイアログを閉じてしまう（何も起きなかったように見える）UXの欠落も修正し、失敗時はダイアログを閉じずエラーメッセージを表示するようにした。`docs/API仕様.md`にもこの挙動を追記済み。

### 結合テストの安定性に関する調査・修正（最重要）

5. 既存のPlaywright結合テストには、過去複数回のセッションにわたって「`I-GEN-04`がフルスイート実行時にのみ断続的にタイムアウトし、単独実行では再現しない（ベニンな環境要因）」という調査記録が残っていたが、本セッションで改めて調査した結果、**これは環境要因ではなく、テストヘルパー自身に実在する既知の修正可能なレースだった**ことが判明した。
   - 原因：`tests/integration/helpers.ts`の`generateCategories()`・`enableCategory()`・`setLeagueFormat()`が、保存・生成ボタン押下後に固定時間（300〜400ms）の`waitForTimeout`だけに頼っており、実際のPOST/PUTレスポンスを待っていなかった。サーバー側の処理がこの固定時間内に完了しない場合、後続の`page.goto()`がブラウザ側から見て未完了のリクエストを打ち切ってしまい（Playwrightの保存済みトレースでも`status: -1`＝クライアント側中断として確認）、画面は生成・更新前の古い状態のまま検証されてしまう（サーバー側の処理自体はバックグラウンドで継続し、後から確認すると正しい状態になっているため、調査時に「アプリの状態自体は正しい」と誤って結論づけやすい）。
   - 修正：上記3つのヘルパーに`page.waitForResponse()` + レスポンス成功確認を追加し、サーバー側の処理完了を待ってから後続操作へ進むようにした。
   - 結果：修正後、フルスイートを4回連続実行して全件OK（失敗・flaky再試行なし）。**過去のセッションで「pre-existing・環境要因・対応不要」と記録していた認識は誤りだったため、該当する開発者向けメモ（セッション間の申し送り記録）を修正済み**。
