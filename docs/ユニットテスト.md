# ユニットテストケース一覧

## 目的

本ドキュメントは、`CLAUDE.md` のテスト方針（単体/結合テストはVitest + React Testing Libraryを用い、リーグ表自動生成・試合順自動生成・審判順自動生成・順位決定ロジックなど「コアロジック」に該当する、間違えやすい機能を重点的にカバーする）に基づき、単体テストで検証すべきケースを列挙する。

- 本書はテストケースの仕様である。実行可能なテストコードは、対応するロジックが定義されている`*.ts`ファイルと同じディレクトリの`*.test.ts`（例：`src/lib/scheduling.test.ts`、`src/lib/ranking.test.ts`、`src/lib/league-matrix.test.ts`、`src/lib/mock-data.test.ts`）として実装している。
- 対象ロジックの一次情報源は `docs/要件定義書.md` 3.4〜3.9。用語は `docs/用語集.md` に準拠する。
- 「得点」「勝点」の多義性に関する注意（用語集参照）は、テスト名・アサーション双方で区別が明確になるようにすること。
- 実行コマンド: `npm test`（Vitest）。
- 本書の「対象関数/モジュール」列は、実装当初は仮称（例：`generateLeagueTable`）で記述していたが、実装時に以下の実在する関数へ対応させた。個別の分離関数として存在しない概念（例：試合全体の勝敗判定）は、それを包含するより大きな関数（`computeStandings`）のテストの中で間接的に検証している。

## カバレッジの考え方

- 上記のうち5章（試合結果自動計算・順位決定ロジック）は要件定義書が「最も間違えやすい」と位置づける領域であるため、境界値（タイ、ゼロ除算、未入力セット）を優先してケースを追加すること。
- 「ベストエフォート」と明記されている項目（試合順・審判順の均等化）は、固定の期待値一致ではなく、しきい値や統計的指標（分散・最大最小差など）でアサーションすること。
