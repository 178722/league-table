# 要件定義書
### プロジェクト名
リーグ戦しようよ（スポーツリーグ管理システム）

## 1. システム概要

### 1.1 背景
スポーツ大会運営において、チーム登録、試合組合せ作成、勝敗入力、順位計算などをExcelで管理しているため、入力ミスや集計ミスが発生している。
これらの業務をシステム化し、大会運営の効率化を図る。

### 1.2 目的
効率化を図るため、以下の機能を提供する。
- 大会情報登録
- 競技情報登録
- 選手(チーム)情報登録
- リーグ表自動生成
- 試合順自動生成
- 審判順自動生成
- 試合結果登録
- 試合結果自動計算
- データ出力


## 2. システム利用者

### 2.1 管理者
大会全体を管理し、以下の機能を利用可能とする。管理者アカウントは単一とし、環境変数（.env）でシードした1アカウントのみで運用する（追加の管理者アカウントを作成する機能は設けない）。
- 大会情報登録・編集・削除
- 競技情報登録・編集・削除
- 選手(チーム)情報登録・編集・削除
- 試合(リーグ表、試合順、審判順)作成
- 試合結果登録
- データ出力

登録済みの大会/競技/選手(チーム)情報は、登録後も編集・削除が可能とする。ただし、試合(リーグ表、試合順、審判順)が既に生成された後に関連する情報を変更する場合は、再生成が必要となる旨を管理者に確認する。競技情報（セット数・順位決定方式等）は、試合結果が1件でも登録されている場合は変更をブロックする（詳細は3.2を参照）。同様に、試合結果が1件でも登録されているカテゴリ内の選手(チーム)情報（カテゴリ・コート選択・コート番号）の変更、試合結果が登録されている選手(チーム)の削除、および試合結果が1件でも登録されている競技情報自体の削除もブロックする（詳細は3.2・3.3を参照）。

大会情報を削除した場合、紐づく競技情報・選手(チーム)情報・試合(リーグ表、試合順、審判順)・試合結果は連鎖的に削除（カスケード削除）される。削除前に確認ダイアログを表示する。

大会には「進行中」「終了」のステータスがあり、登録時のデフォルトは「進行中」とする。管理者は任意のタイミングで「大会を終了する」操作によりステータスを「終了」に切り替えることができ、また「終了」を取り消して「進行中」に戻すこともできる。「終了」の間は、大会情報・競技情報・選手(チーム)情報の編集、および試合結果の入力・修正を一切行えない（閲覧のみ可能）。

### 2.2 参加者
参加者は、以下の機能を利用可能とする。ログインは不要とし、URL等を知っていれば誰でも閲覧できる。閲覧用URLは大会単位で発行し、1つのURLで大会内の全カテゴリの試合結果・順位表を閲覧できる。
- 試合結果閲覧

### 2.3 閲覧モード利用者
ログイン画面（A1）に、ID・パスワードなしで入れる「閲覧モードで見る」ボタンを用意する。閲覧モードでは、管理者向け画面（A2〜A8）を2.1と同じ範囲で閲覧できるが、登録・編集・削除・試合(リーグ表、試合順、審判順)生成・試合結果入力・バックアップ作成・リストアなど、データを書き換える操作は一切行えない（該当する操作のボタンはUI上disabledにし、APIレベルでも拒否する）。


## 3. 機能要件

本章の各項目表で「MAX：全角n文字」と定めている項目について、上限を超える入力はエラーとして保存を拒否する（自動切り詰めは行わない）。

### 3.1 大会情報登録
#### 概要
大会情報を登録する。
#### 項目
| 項目 | 必須 | 条件 | 登録内容 |
|---|---|---|---|
| 大会名 | ◯ |  | MAX：全角50文字、デフォルト：空白 |
| 開催日 | ◯ |  | カレンダー、デフォルト：登録日 |
| 開催場所 | ◯ |  | MAX：全角50文字、デフォルト：空白 |
| カテゴリA | ◯ |  | MAX：全角25文字、デフォルト：空白 |
| カテゴリB |  | 必要な場合(チェックボックス) | MAX：全角25文字、デフォルト：空白 |
| カテゴリC |  | 必要な場合(チェックボックス)| MAX：全角25文字、デフォルト：空白 |
| カテゴリD |  | 必要な場合(チェックボックス)| MAX：全角25文字、デフォルト：空白 |
| カテゴリE |  | 必要な場合(チェックボックス)| MAX：全角25文字、デフォルト：空白 |
| カテゴリF |  | 必要な場合(チェックボックス)| MAX：全角25文字、デフォルト：空白 |
| カテゴリG |  | 必要な場合(チェックボックス)| MAX：全角25文字、デフォルト：空白 |
| カテゴリH |  | 必要な場合(チェックボックス)| MAX：全角25文字、デフォルト：空白 |
| カテゴリI |  | 必要な場合(チェックボックス)| MAX：全角25文字、デフォルト：空白 |
| カテゴリJ |  | 必要な場合(チェックボックス) | MAX：全角25文字、デフォルト：空白 |
#### 条件
- 同一大会内でカテゴリ名（カテゴリA〜J）の重複は禁止する
- 一度有効化したカテゴリ（B〜J）に競技情報または選手(チーム)情報が登録済みの場合、そのカテゴリを無効化（チェックを外す）することはできない
- カテゴリの無効化（チェックを外して保存）は、そのカテゴリの競技情報設定を破棄する実質的な削除操作である。競技情報登録画面（3.2）に専用の削除ボタンは設けない。再度チェックして保存すると、未使用状態（デフォルト設定）のカテゴリとして新規登録される
- 大会のステータス（進行中/終了）の管理方法は2.1を参照。ステータスが「終了」の間は大会情報の編集を行えない
#### 例
- 大会名：バレーボール大会
- 開催日：yyyy/mm/dd
- 開催場所：体育館
- カテゴリA：フリー

### 3.2 競技情報登録
#### 概要
競技情報を、大会情報登録のカテゴリ別に登録する。
#### 項目
| 項目 | 必須 | 条件 | 登録内容 |
|---|---|---|---|
| セット数 | ◯ |  | 範囲：1〜5、デフォルト：1 |
| 順位決定方式 | ◯ |  | 選択：勝敗方式 or 勝点方式：デフォルト：勝敗方式 |
| 勝利勝点 |  | 順位決定方式が、勝点方式の場合 | 範囲：0〜5、デフォルト：3 |
| 引分勝点 |  | 順位決定方式が、勝点方式の場合 | 範囲：0〜5、デフォルト：1 |
| 敗北勝点 |  | 順位決定方式が、勝点方式の場合 | 範囲：0〜5、デフォルト：0 |
| コート数 | ◯ |  | 範囲：1〜5、デフォルト：1 |
| 1コート最大選手(チーム)数 | ◯ |  | 範囲：2〜10、デフォルト：5 |
| リーグ形式 | ◯ | コート数が2以上の場合のみ選択可 | 選択：独立リーグ or 単一リーグ、デフォルト：独立リーグ |
#### 条件
- 勝点：勝利勝点 > 引分勝点 > 敗北勝点
- リーグ形式（コート数が2以上の場合のみ意味を持つ）：
  - 独立リーグ：コート毎に別々の総当たり戦（リーグ表・試合順・審判順・勝敗表）として扱う（3.4〜3.6参照）
  - 単一リーグ：複数コートにまたがる1つの総当たり戦（リーグ表・試合順・審判順・勝敗表）として扱う（3.4〜3.6参照）
  - コート数が1の場合は常に独立リーグ扱い（単一リーグとの区別が意味を持たないため）
- 1コート最大選手(チーム)数は2以上でなければならない（1コートに1チームまでしか配置できない設定は、各コート最低2チーム必須の条件と矛盾するため、登録時点でエラーとする）
- 試合結果が1件でも登録されている場合、セット数・順位決定方式・勝利勝点/引分勝点/敗北勝点・コート数・1コート最大選手(チーム)数の変更はブロックする
- 競技情報（カテゴリのルール設定）自体の削除は、本画面に専用の削除ボタンを設けず、大会情報登録画面（3.1）のカテゴリチェックボックスを外して保存することで行う（詳細は3.1を参照）
- 試合結果が1件でも登録されている競技情報（カテゴリのルール設定）自体の削除（チェックを外すこと）はブロックする
- 選手(チーム)情報が1件でも登録されているカテゴリの競技情報自体の削除（チェックを外すこと）はブロックする（試合結果の有無に関わらない）
#### 例
- セット数：5セット
- 順位決定方式：勝点方式
- 勝利勝点：3
- 引分勝点：1
- 敗北勝点：0
- コート数：1
- 1コート最大選手(チーム)数：5

### 3.3 選手(チーム)情報登録
#### 概要
選手(チーム)情報を登録する。
#### 項目
| 項目 | 必須 | 条件 | 登録内容 |
|---|---|---|---|
| 選手(チーム)名 | ◯ |  | MAX：全角10文字、デフォルト：空白 |
| 所属 |  |  | MAX：全角10文字、デフォルト：空白 |
| カテゴリ | ◯ |  | 選択：大会情報登録で有効なカテゴリ、デフォルト：カテゴリA |
| コート選択 |  | 競技情報登録のコート数が、2以上の場合 | 選択：自動 or 手動 |
| コート番号 |  | コート選択が、手動の場合 | 範囲：1〜競技情報登録のコート数、デフォルト：1 |
#### 条件
- 選手(チーム)名：同一大会・同一カテゴリ内で重複不可（別大会・別カテゴリでは同名登録可）
- 所属：重複可、常に任意項目（個人/団体の区別は設けない）
- コート選択が、手動の場合：同一カテゴリの同一コート番号の選手(チーム)数 <= 競技情報登録の1コート最大選手(チーム)数
- コート選択が、手動の場合：コート番号は競技情報登録の「コート数」以下でなければならない
- 同一カテゴリの登録選手(チーム)数の合計は、競技情報登録の「コート数 × 1コート最大選手(チーム)数」を超えてはならない（超える登録はエラーとする）
- 試合結果が1件でも登録されているカテゴリ内の選手(チーム)は、カテゴリ・コート選択・コート番号の変更をブロックする
- 試合結果が登録されている選手(チーム)の削除はブロックする
#### 例
- 選手(チーム名)：Aさん、Bさん
- 所属：熊本
- カテゴリ：カテゴリA
- コート選択：手動
- コート番号：1

### 3.4 リーグ表自動生成
#### 概要
リーグ表を自動生成する。カテゴリ別に、競技情報登録の「リーグ形式」（3.2参照）に応じて以下のいずれかの方式で生成する。
##### 独立リーグの場合（コート数1、またはコート数2以上かつリーグ形式が独立リーグ）
1. 競技情報登録のコート数が、2以上の場合、コート別の条件を加える
  - 選手(チーム)情報登録のコート選択が、自動の場合、ランダムにコートを振り分ける
    - 1コートの振り分け選手(チーム)数 = 同一カテゴリの選手(チーム)数 ÷ 競技情報登録の同一カテゴリのコート数
    - 割り切れない場合は、前から順に1人(チーム)ずつ加えて振り分ける
    - 同一カテゴリ内に手動選択の選手(チーム)が存在する場合、手動指定済みの枠数を差し引いた残り枠に自動選択の選手(チーム)を振り分ける
  - 選手(チーム)情報登録のコート選択が、手動の場合、コート番号に従ってコートを振り分ける
2. カテゴリごとの「コート」は、カテゴリごとに独立した物理コート（別会場・別時間帯運用を想定）とし、他カテゴリとのコート資源の競合は考慮しない
3. コート毎に別々の総当たり戦（リーグ表・試合順・審判順・勝敗表）として生成する
##### 単一リーグの場合（コート数2以上かつリーグ形式が単一リーグ）
1. 選手(チーム)情報登録のコート選択・コート番号は使用しない（カテゴリ全体を1つのリーグとして扱うため、選手(チーム)は特定の物理コートに固定されない）
2. カテゴリ全選手(チーム)の総当たり組合せを1つ生成し、複数の物理コートへ試合を振り分けて並行開催する（詳細は3.5参照）
3. リーグ表・勝敗表（順位表）はカテゴリ全体で1つに統合する
#### 条件（共通）
- リーグ表（行・列）・試合順の対戦カードの並び順は、選手(チーム)情報登録順ではなく、リーグ表自動生成の実行時点でランダムに決定する（再生成するたびに並び順が変わりうる。独立リーグの場合はコート毎に独立してランダム化する）
- 「自動」選択の選手(チーム)のコート割当は、リーグ表自動生成の実行時点で決定する（再生成するたびに割当結果が変わりうる。単一リーグの場合はこの割当自体を行わない）
- 同一カテゴリの参加選手(チーム)数は2以上を必須とし、1以下の場合はリーグ表自動生成をエラーとする
- 同一カテゴリに試合結果が1件でも入力済みの場合、リーグ表自動生成（再生成）をエラーとする（エラーダイアログ文言：「試合結果が入力されています。試合結果を削除して下さい。」）。再生成する場合は、事前に試合結果を削除する必要がある
- リーグ表・試合順・審判順は常に一括で生成・再生成する（試合順・審判順のみを個別に再生成する機能は設けない）
#### 条件（独立リーグのみ）
- 各コートに割り振られる選手(チーム)数も2以上を必須とし、1以下のコートが生じる場合はリーグ表自動生成をエラーとする
- 同一カテゴリの参加選手(チーム)数が「競技情報登録のコート数×1コート最大選手(チーム)数」を超える場合、リーグ表自動生成をエラーとする（エラーダイアログ文言：「想定を超える選手(チーム)が登録されています。競技情報のコート数、または、１コート最大選手(チーム)数を変更して下さい。」）
#### 条件（単一リーグのみ）
- 「1コート最大選手(チーム)数」による人数上限は適用しない（カテゴリ全体で参加選手(チーム)数2以上のみが条件）
#### 試合数の計算方法
試合数 = N × (N - 1) ÷ 2
#### 組合せ例(4チーム)
1. A - B
2. A - C
3. A - D
4. B - C
5. B - D
6. C - D

### 3.5 試合順自動生成
#### 概要
試合順を自動生成する。
#### 条件
- 同一チームの連続試合を避ける（可能な限り均等にするベストエフォートでよく、厳密な数値基準は設けない）
- コート数を考慮する
- 休憩時間を均等化する（可能な限り均等にするベストエフォートでよく、厳密な数値基準は設けない）
- 単一リーグの場合：総当たり組合せを対戦が重複しない単位（ラウンド）ごとに区切り、ラウンドをまたがずにコート数ぶんずつ時間帯（試合順）へ詰める。同一時間帯に複数コートで並行開催する試合は、同じ「試合順」番号を共有する（表示上は試合順表に「コート」列を設け、どのコートの試合かを示す）

### 3.6 審判順自動生成
#### 概要
審判順を自動生成する。
試合順の自動生成で出力される表に付加する
審判は、その時間帯に試合をしていない同一カテゴリの他の選手(チーム)が兼務する（審判専用のマスタ登録は行わない）
優先順位は「試合＞審判」とする：対戦カード（どの選手(チーム)同士が対戦するか）を先に確定し、その後に各試合の時間帯で空いている選手(チーム)から審判を選ぶ
#### 条件
- 同一チームの連続審判を避ける（可能な限り均等にするベストエフォートでよく、厳密な数値基準は設けない）
- コート数を考慮する
- 審判回数を均等化する（可能な限り均等にするベストエフォートでよく、厳密な数値基準は設けない）
- 独立リーグの場合：審判候補は同一コート内でその試合に出場していない選手(チーム)
- 単一リーグの場合：審判候補は、その試合と同じ時間帯（試合順）に他のコートでも試合をしていない、同一カテゴリの選手(チーム)（対戦中の2者だけでなく、同時刻に他コートで試合中の選手(チーム)も候補から除外する）
- 単一リーグの場合、同一時間帯（試合順）に複数コートが並行開催するため、同じ選手(チーム)を同時に2つ以上のコートの審判として重複割当してはならない（物理的に同時に2箇所で審判はできないため）。空いている選手(チーム)の人数が同時進行コート数より少ない場合、その時間帯のうち割り当てきれなかった分のコートは審判候補なしとして扱う（次項の「運営スタッフ」表示へフォールバックする）
- 対戦カードの2者以外に審判を頼める相手がいない場合（同一コートの参加者が2名のみ、または単一リーグで全員が同時刻に試合中等）は、審判欄に赤字で「運営スタッフ」と表示する（5章「審判要員不足時の対応」への対応）。単一リーグで同一時間帯（試合順）の全コート、または一部のコートが同時にこの状態になる場合、複数コートに同時に「運営スタッフ」が表示されてもよい（コート間で審判候補を融通する仕組みは設けない）

### 3.7 試合結果登録
#### 概要
試合結果を登録する。
#### 項目
- 点数(範囲：0〜999、デフォルト：0)
  - 競技情報登録のセット数分の入力ができる
  - セット毎に勝敗マークを自動付加する(◯：勝ち、ー：引分、空白：負け)
#### 条件
- 点数が多い：勝ち
- 点数が同じ：引分
- 点数が少ない：負け
- 1試合（複数セット）の場合、試合全体の勝ち/引分/負けは、勝ちセット数の多い方を試合の勝ちとし、勝ちセット数が同数の場合は引分とする
- セット数が複数設定されている場合、途中で勝敗が決した時点で残りのセットは入力不要とする。未入力のセットは得セット数・失セット数（セット率の算出対象）に含めない
- 登録済みの試合結果は修正（訂正入力）可能とする。修正時は勝敗表を自動的に再集計する
- 試合順表の結果列は、未入力の場合「未入力」ボタン、入力済みの場合「入力済」ボタン＋「削除」ボタンを表示する。いずれのボタンも押下すると結果入力ダイアログを開く（結果入力はそこで行う）。「削除」ボタンのみ押下すると即座に試合結果を削除し未入力状態に戻す（確認ダイアログは設けない）。削除後は勝敗表・選手(チーム)の試合結果登録済みフラグを自動的に再集計する
- 複数端末から同一の試合結果を同時に入力・修正した場合、排他制御は行わず、最後に保存した内容で単純に上書きする
#### 例
- (◯)  15 -  14 (　)
- (ー)  20 -  20 (ー)
- (　)  14 - 999 (◯)

### 3.8 試合結果自動計算
#### 概要
試合結果が登録されたら、自動集計し、勝敗表を自動生成する。
勝敗表は、リーグ表の右側に追加する
#### 集計項目
- 勝ち数
- 引分数
- 負け数
- セット率
- 得点
- 失点
- 得点率
- 勝点
#### セット率・得点率の算出式
- セット率 ＝ 得セット数 ÷ 失セット数
- 得点率 ＝ 得点 ÷ 失点
- いずれも分母が0の場合（セット率は無敗、得点率は無失点）は無限大として扱い、他の有限な値より常に上位とする。分子・分母がともに0（試合未実施）の場合は0として扱う。画面上の表示はいずれも無限大の場合「MAX」とする
#### 順位決定順序
##### 競技情報登録の順位決定方式が、勝敗方式の場合
- 勝敗(勝ち数、引分数、負け数)
- セット率
- 得点率
- 対戦結果
- じゃんけん
##### 競技情報登録の順位決定方式が、勝点方式の場合
- 勝点
- セット率
- 得点率
- 対戦結果
- じゃんけん
#### 対戦結果による判定方法
- 3者以上が同成績でタイした場合、タイした者同士の試合結果のみを抽出したミニリーグとして勝敗・セット率・得点率等を再集計し、順位を決定する
#### 最終順位の手動確定
- 対戦結果でも決着しない場合の「じゃんけん」はシステム外（参加者同士）で行われるため、管理者がその結果を踏まえて最終順位を手動で上書き・確定できる機能を設ける
- 手動確定した順位は勝敗表（順位表）へ直接反映するのみで、確定状態自体を記憶する仕組みは持たない。そのため、確定後に同一コート・カテゴリの別の試合結果を保存（修正・削除）すると、勝敗表は試合結果から毎回自動的に丸ごと再集計されるため、タイ条件が解消していなければ再び「じゃんけん待ち」に戻る（＝手動確定は次にその組の試合結果が保存されるまでの暫定的な反映であり、恒久的な上書きではない）
#### 勝敗表
- 勝ち数
- 引分数
- 負け数
- セット率
- 得点
- 失点
- 得点率
- 勝点(競技情報登録の順位決定方式が、勝点方式の場合)
- 順位

### 3.9 データ出力
#### 概要
大会全体のデータを1つのExcelファイル（.xlsx）として出力する。「データ出力」ボタン押下で即座にファイルを生成してダウンロードし、出力完了を知らせるダイアログのみを表示する（出力専用の中間画面は設けない）。
#### シート構成
- シート1：大会情報（大会名・開催日・開催場所・ステータスに加え、カテゴリ一覧も含む）
- シート2：競技情報（縦軸：カテゴリ、横軸：セット数・順位決定方式・勝点・コート数・1コート最大選手(チーム)数等の設定内容、表形式。生成状況は含まない）
- シート3：選手(チーム)（大会全体の選手(チーム)名・所属・カテゴリの一覧。コート選択・コート番号は含まない）
- シート4以降：カテゴリ・パート（コート）毎のリーグ表・勝敗表（順位表）、1シート1表形式（未生成のカテゴリは対象外）


## 4. 非機能要件
### 対応環境
- 対応デバイス：PCのみを想定する（レスポンシブ対応は不要）
- 対応ブラウザ：主要モダンブラウザ（Google Chrome、Microsoft Edge、Safari）の最新版
- 動作環境：Electronによるデスクトップアプリとして配布し、インターネット接続の有無に関わらず運営者のPC1台の上でサーバー・ブラウザが完結して動作する（LAN・他端末からの接続は想定しない）
### 性能
- リーグ表自動生成：3秒以内
- 試合順(審判順)自動生成：3秒以内
- 試合結果自動計算：1秒以内
### セキュリティ
- ログイン認証（管理者のみ対象。参加者はログイン不要）
- パスワード暗号化
- 通信はHTTP（本アプリはインターネット接続なしの単一PC環境での利用を前提とし、HTTPS化は行わない）
- 管理者パスワードは最低8文字以上を必須とする
- 初期管理者アカウントは環境変数（.env）でID/パスワードをシードして作成する（管理者登録用のサインアップ画面は設けない）
- 管理者は、シードされたID・パスワードをいつでも変更できる。変更はログイン画面のダイアログから行い、未ログイン状態でも現在のID・パスワードの入力を本人確認として実行できる
### バックアップ
- 手動バックアップ（契機表記：「手動」）
- ログアウト時のバックアップ（契機表記：「ログアウト」）。ログアウト操作時は「ログアウトしますか？」の確認に続けて、ログアウトする場合のみ「バックアップを作成しますか？」の確認を行い、その選択に応じてバックアップの有無を決定する（選択によらない無条件の自動バックアップは行わない）
- バックアップ履歴から対象（作成日時）を選択して復元（リストア）できる機能。操作順は、1. バックアップデータ（作成日時）の選択、2. 復元ボタン押下、3. 復元実行最終確認（ダイアログ）とする。復元は選択したバックアップの内容で業務データ（大会・競技情報・選手(チーム)・試合・勝敗表）を完全に上書きするため、実行前に確認ダイアログ内で注意文言を表示する。バックアップ履歴自体は復元対象に含めない（復元後も、復元時点より後に作成されたバックアップを含めすべての履歴から選択できる）
- バックアップの保持数は20件を上限とし、超過した場合は作成日時が最も古いものから削除する
- バックアップ履歴は作成日時の期間で絞り込んで表示できる。作成日時は秒単位まで記録・表示する
- バックアップファイル（選手(チーム)の氏名・所属等の個人情報を含むJSON）はサーバー側にのみ保存し、管理者による個別ダウンロードは提供しない（復元はバックアップ履歴からの選択により行うため、ダウンロード→再アップロードという手順を必要としない）
